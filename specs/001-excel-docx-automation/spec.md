# Feature Specification: Excel到Docx自动化报告生成系统

**Feature Branch**: `001-excel-docx-automation`  
**Created**: 2025-10-24  
**Status**: Draft  
**Input**: User description: "Excel到Docx模板的自动化报告生成：从Excel结果表中提取信息，填充进docx模板，批量生成终版医疗报告"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 单个报告生成 (Priority: P1)

医疗报告处理人员需要从Excel结果表中读取单个患者的基因检测数据，自动填充到标准docx模板中，生成一份格式规范、内容完整的终版医疗报告。

**Why this priority**: 这是整个系统的核心功能，是最小可用产品（MVP）。单个报告生成成功后，即可交付使用并验证整个数据映射和模板填充逻辑的正确性。

**Independent Test**: 使用提供的示例Excel文件（MLF2509307001T_MLB2509307001.result.xlsx），成功生成一份完整的终版报告，报告内容与历史参考报告在结构和关键字段上保持一致。

**Acceptance Scenarios**:

1. **Given** Excel结果表包含完整的患者信息和检测数据, **When** 用户指定该Excel文件并执行生成命令, **Then** 系统成功生成一份docx报告，包含正确的患者姓名、样本编号、检测结果等所有关键字段
2. **Given** Excel中存在变异明细数据表, **When** 系统处理该表格, **Then** 生成的报告中的变异表格正确显示所有变异记录，每行包含基因名、变异位点、丰度、深度等完整信息
3. **Given** Excel中包含MSI/TMB指标数据, **When** 系统读取这些数据, **Then** 报告中正确展示MSI状态（MSI-H/MSS/MSI-L）和TMB数值
4. **Given** 生成过程中遇到数据处理, **When** 处理完成, **Then** 输出日志文件记录处理时间、数据来源、模板版本等关键信息

---

### User Story 2 - 批量报告生成 (Priority: P2)

医疗报告处理人员需要一次性处理多个患者的检测结果，从包含多行样本数据的Excel表或多个Excel文件中，批量生成所有患者的终版报告。

**Why this priority**: 医疗机构通常需要处理大量样本，批量处理功能显著提高工作效率，减少重复操作。在单个报告生成功能验证通过后，批量处理是自然的扩展。

**Independent Test**: 提供包含10个样本数据的Excel表，系统能在合理时间内（<5分钟）生成10份独立的报告文件，每份报告对应一个样本且数据准确。

**Acceptance Scenarios**:

1. **Given** Excel文件包含10行样本数据, **When** 用户执行批量生成命令, **Then** 系统生成10个独立的docx文件，文件命名规范为"{患者姓名}_{样本编号}_{项目名称}_{报告日期}_终版.docx"
2. **Given** 批量处理过程中某个样本数据不完整, **When** 系统检测到缺失关键字段, **Then** 跳过该样本并在日志中记录错误信息，继续处理其他样本
3. **Given** 批量生成包含50个样本, **When** 处理完成, **Then** 生成汇总日志显示成功数量、失败数量、缺失字段统计、平均处理时间等信息
4. **Given** 用户指定输出目录, **When** 批量生成执行, **Then** 所有报告文件输出到指定目录，按日期或项目类型分类存放

---

### User Story 3 - 多项目类型自动识别 (Priority: P3)

系统能够自动识别不同的检测项目类型（如"301基因+MSI"、"358基因+MSI"、"肺癌甲基化"等），根据项目类型选择对应的模板或触发特定的条件内容块。

**Why this priority**: 不同项目类型报告的结构和内容有差异，自动识别可以避免手动选择模板，减少人为错误。这是在核心功能完善后的智能化提升。

**Independent Test**: 使用包含不同项目类型的Excel数据（301基因、358基因、甲基化），系统能正确识别并应用对应模板，生成的报告结构符合该项目类型的标准格式。

**Acceptance Scenarios**:

1. **Given** Excel中"项目名称"字段为"结直肠癌301基因+msi", **When** 系统识别项目类型, **Then** 自动选择或触发301基因模板的内容结构
2. **Given** Excel中标识为"肺癌甲基化"项目, **When** 系统处理该数据, **Then** 报告中包含甲基化特有的章节（如甲基化结论、甲基化位点表），而隐藏基因变异相关章节
3. **Given** 项目类型字段缺失或无法识别, **When** 系统尝试分类, **Then** 使用默认通用模板并在日志中记录警告信息
4. **Given** 新增一种项目类型, **When** 在配置文件中添加该类型的识别规则和模板映射, **Then** 系统无需代码修改即可支持新项目类型

---

### User Story 4 - 模板变量化与字段映射管理 (Priority: P2)

技术人员或配置管理员需要能够轻松修改和维护模板占位符与Excel列名之间的映射关系，支持字段同义词（如"样本编号"、"送检编号"、"条码号"都映射到同一变量）。

**Why this priority**: 医疗报告的字段可能随着业务调整而变化，灵活的映射配置可以避免硬编码，降低维护成本。这是系统可维护性的关键。

**Independent Test**: 修改mapping.yaml配置文件，将某个新的Excel列名添加为已有变量的同义词，无需修改代码，系统能正确识别并填充数据。

**Acceptance Scenarios**:

1. **Given** mapping.yaml定义了patient_name对应["患者姓名", "姓名"], **When** Excel中使用"姓名"作为列名, **Then** 系统能正确识别并提取该字段值
2. **Given** 需要新增字段映射, **When** 在mapping.yaml中添加新的映射项, **Then** 系统重启后自动加载新配置，无需代码变更
3. **Given** Excel列名与配置的所有同义词都不匹配, **When** 系统尝试映射字段, **Then** 在日志中记录缺失字段，报告中对应位置使用占位符"-"
4. **Given** 映射配置文件格式错误, **When** 系统启动加载配置, **Then** 显示清晰的错误提示，指明错误位置和原因

---

### Edge Cases

- **Excel文件损坏或无法打开**: 系统应捕获异常，记录错误日志，终止处理并提示用户检查文件
- **Excel中关键字段（如患者姓名、样本编号）为空**: 系统应中止该样本的报告生成，记录详细错误信息到日志
- **变异明细表为空（未检出变异）**: 报告中对应章节显示"未检出致病性变异"或隐藏该表格
- **日期格式不统一**（如"2025-10-24"、"2025/10/24"、"20251024"）: 系统应自动识别并转换为统一格式"YYYY-MM-DD"
- **数值字段包含非数字字符**: 系统应尝试清洗（去除空格、全角字符），失败则记录警告并使用"-"占位
- **Docx模板文件缺失或损坏**: 系统启动时检查模板文件完整性，缺失时拒绝执行并明确提示
- **输出目录权限不足或磁盘空间不足**: 捕获IO异常，明确提示用户并终止操作
- **Excel中包含合并单元格**: 系统应正确处理合并单元格数据提取，避免数据错位
- **超大Excel文件（>100MB或>10000行）**: 系统应采用流式读取，避免内存溢出，并在日志中记录处理进度

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须能够读取Excel文件（.xlsx格式），提取指定sheet中的数据表
- **FR-002**: 系统必须支持从Excel中提取单值字段（如患者姓名、样本编号、报告日期等）
- **FR-003**: 系统必须支持从Excel的表格sheet中提取多行数据（如变异明细、融合、CNV等）
- **FR-004**: 系统必须能够读取并解析docx模板文件，识别其中的占位符（支持Jinja2风格的变量、循环、条件语法）
- **FR-005**: 系统必须将Excel提取的数据按照字段映射规则填充到docx模板的对应占位符
- **FR-006**: 系统必须支持表格循环渲染（如变异明细表每行一个变异记录）
- **FR-007**: 系统必须支持条件内容渲染（如MSI-H时显示特定段落，MSS时隐藏）
- **FR-008**: 系统必须根据项目类型字段自动选择对应的模板文件或触发模板内条件块
- **FR-009**: 系统必须支持批量处理，从单个Excel多行或多个Excel文件生成多份报告
- **FR-010**: 系统必须按照规范命名输出的报告文件：`{patient_name}_{sample_id}_{project_name}_{report_date}_终版.docx`
- **FR-011**: 系统必须提供字段映射配置文件（mapping.yaml/json），支持字段同义词定义
- **FR-012**: 系统必须在关键字段（patient_name, sample_id）缺失时中止生成并报错
- **FR-013**: 系统必须对非关键字段缺失时使用默认值"-"填充并记录警告日志
- **FR-014**: 系统必须对数值字段进行格式化处理（如AF保留2位小数并添加%，日期统一为YYYY-MM-DD）
- **FR-015**: 系统必须清洗文本数据，去除全角/半角混用、多余空格、不可见字符
- **FR-016**: 系统必须验证生成的报告文件可正常打开且内容完整
- **FR-017**: 系统必须提供命令行接口，支持指定输入Excel、输出目录、模板选择等参数
- **FR-018**: 系统必须支持扫描已有终版报告，辅助提取共性版式和可变元素（初始化功能）

### Quality Requirements (按宪章要求)

- **QR-001**: Code quality - 代码必须通过静态分析（pylint/flake8），无严重问题，代码复杂度<10
- **QR-002**: Testing - 核心逻辑测试覆盖率必须 ≥ 80%，包括数据提取、字段映射、模板渲染、异常处理的单元测试
- **QR-003**: User experience - 错误信息必须清晰可操作（如"缺失关键字段：患者姓名（patient_name）"），无技术术语（如不显示Python异常堆栈）
- **QR-004**: Performance - 单个报告生成时间 < 10秒，Excel文件解析 < 5秒，批量处理50个样本 < 5分钟
- **QR-005**: Observability - 关键操作必须记录结构化日志（包括时间戳、操作类型、输入文件、输出文件、成功/失败状态、处理时长）
- **QR-006**: Data integrity - 所有数据处理必须可追溯，日志中记录源Excel文件路径、模板版本、映射配置版本
- **QR-007**: Security - 必须使用脱敏后的测试数据进行开发和测试，禁止在非生产环境使用真实患者隐私数据
- **QR-008**: Maintainability - 字段映射、模板选择规则必须外部化配置，避免硬编码，支持无代码修改的配置更新

### Key Entities *(include if feature involves data)*

- **ExcelDataSource**: Excel结果表数据源，包含属性：文件路径、包含的sheet列表、每个sheet的列名和行数据
- **FieldMapping**: 字段映射规则，包含属性：变量名（如patient_name）、对应的Excel列名同义词列表、数据类型、格式化规则、是否必填
- **DocxTemplate**: Docx模板文件，包含属性：模板文件路径、占位符列表、条件块定义、循环块定义、适用的项目类型
- **ReportData**: 待填充的报告数据模型，包含属性：单值字段（患者信息、项目信息、结论）、表格字段（变异列表、融合列表、CNV列表）、元数据（生成时间、模板版本、数据来源）
- **GeneratedReport**: 生成的报告，包含属性：输出文件路径、文件名、生成状态（成功/失败）、错误信息、生成时长
- **ProcessLog**: 处理日志，包含属性：时间戳、操作类型、输入文件、输出文件、成功/失败状态、处理时长、错误详情、缺失字段清单

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 使用示例Excel文件（MLF2509307001T_MLB2509307001.result.xlsx）能够在10秒内成功生成一份完整的终版报告
- **SC-002**: 生成的报告与历史参考报告在关键字段（患者信息、检测结果、变异表格）上内容一致性达到100%
- **SC-003**: 批量处理50个样本的总时间不超过5分钟，平均每个报告生成时间<6秒
- **SC-004**: 系统对包含所有必填字段的Excel数据成功率达到100%，对缺失关键字段的数据能够100%正确识别并报错
- **SC-005**: 日志文件完整记录每次生成的关键信息（输入文件、模板版本、成功/失败、耗时），日志可读性评分≥4/5（由用户评估）
- **SC-006**: 字段映射配置修改后，无需代码变更，系统重启即可生效，配置变更成功率100%
- **SC-007**: 支持至少3种不同项目类型（301基因、358基因、肺癌甲基化）的自动识别和模板选择，识别准确率100%
- **SC-008**: 数值格式化准确率100%（日期统一为YYYY-MM-DD，AF保留2位小数+%，深度为整数）
- **SC-009**: 异常处理覆盖率100%（文件损坏、权限不足、磁盘空间不足、数据格式错误均有明确提示）
- **SC-010**: 用户首次使用系统（包括安装、配置、生成第一份报告）所需时间不超过30分钟

### Assumptions

- Excel文件格式为.xlsx（不支持旧版.xls）
- Excel中每个sheet的第一行为列名（表头）
- Docx模板使用Jinja2风格的占位符语法
- 系统运行环境为Linux/Windows，Python 3.8+
- 用户具备基本的命令行操作能力
- 模板文件和映射配置文件存放在固定的目录结构（如templates/、mapping/）
- 生成的报告不包含数字签名和盖章（签名盖章由后续流程处理）
- 同一Excel文件中不同项目类型的样本需分开处理（每次处理单一项目类型）

### Dependencies

- 需要已有的终版报告样本用于模板抽取和验证（已提供）
- 需要示例Excel结果表用于测试和验证（已提供：MLF2509307001T_MLB2509307001.result.xlsx）
- 需要明确不同项目类型的字段差异和特有章节（参考"肺癌甲基化检测"资料）
